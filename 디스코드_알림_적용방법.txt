[디스코드 알림 연동 - 순서대로]

A. 디스코드에서 웹훅 만들기 (2분)
 1. 알림만 받을 나만의 서버가 없으면 새로 만든다 (서버 추가 > 직접 만들기 > 나와 친구들을 위한 서버)
 2. 알림 채널(예: #코칭-알림) 설정(톱니바퀴) > 연동 > 웹후크 > 새 웹후크 > 'URL 복사'
 3. 이 URL은 비밀번호와 같다. 채팅이나 GitHub, 사이트 코드에 붙이지 말 것 (누구나 그 채널에 글을 쓸 수 있게 됨)
 4. 휴대폰 알림: 디스코드 앱에서 그 채널 길게 누르기 > 알림 설정 > '모든 메시지'

B. Firebase 서비스 계정 키 받기 (서버가 Firestore를 읽기 위한 열쇠, 2분)
 1. Firebase 콘솔 > 프로젝트 설정(톱니바퀴) > 서비스 계정 > '새 비공개 키 생성' > 키 JSON 파일 다운로드
 2. 이 파일도 비밀이다. GitHub에 올리지 말고, 쓴 뒤에는 컴퓨터에서 지워도 된다 (필요하면 콘솔에서 다시 생성 가능)

C. Vercel 환경변수 넣기
 Vercel > 프로젝트 > Settings > Environment Variables 에서 3개 추가 (Production, Preview, Development 모두 체크)
 - DISCORD_WEBHOOK_URL    = A에서 복사한 웹훅 URL
 - FIREBASE_SERVICE_ACCOUNT = B에서 받은 JSON 파일 내용 전체를 그대로 붙여넣기
 - SITE_URL (선택)          = https://woojin-valorant-coaching.vercel.app

D. 파일 덮어쓰기
 1. 이 zip을 풀어 아래를 C:\woojin-coaching 에 복사
    - api/notify.js            (새 파일, 폴더째 복사)
    - src/components/KageLanding.jsx
    - vercel.json
 2. 터미널(C:\woojin-coaching)에서:  npm install firebase-admin
    (package.json 과 package-lock.json 이 바뀐다. 이 둘도 GitHub에 같이 올려야 한다)
 3. GitHub에 push -> Vercel이 자동 배포 (환경변수는 C를 먼저 해 두어야 반영됨. 나중에 넣었다면 Deployments > Redeploy)

E. 확인
 1. 배포가 끝나면 사이트에서 신청을 하나 제출 -> 몇 초 안에 디스코드 채널에 '새 코칭 신청' 알림이 와야 한다
 2. 후기 제출 -> '새 후기 (승인 대기)', 질문 남기기 -> '새 FAQ 질문' 알림
 3. 알림이 안 오면: Vercel > 프로젝트 > Logs(또는 Functions) 에서 /api/notify 응답 확인
    - 500 webhook-config : DISCORD_WEBHOOK_URL 이 없거나 형식이 다름
    - 500 firebase-config : FIREBASE_SERVICE_ACCOUNT 가 없거나 JSON 이 깨짐
    - 502 discord : 웹훅이 삭제됐거나 주소가 틀림
    - 404 not-found : 서비스 계정 키가 다른 Firebase 프로젝트 것
 4. 테스트로 만든 신청·후기·질문은 /admin 에서 삭제

[동작 방식 한 줄 정리]
저장이 끝나면 사이트가 /api/notify 에 '종류와 문서 번호'만 알려 준다 -> 서버가 Firestore에서 그 문서를 직접 읽어 진짜인지 확인 -> 디스코드 웹훅으로 전송. 문서마다 알림은 한 번만 가고, 알림에는 디스코드 ID와 고민 내용은 넣지 않는다.
